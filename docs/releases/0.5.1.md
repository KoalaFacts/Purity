# Purity 0.5.1 release notes

Purity 0.5.1 completes the reorganization of the framework into focused packages
and reduces the compressed npm archives needed to install core. Upgrade all Purity packages
together and rebuild both client and server output.

## Upgrade from 0.4.0

Router, browser signals, actions, query, islands and compiler imports have
moved out of `@purityjs/core`. Install their new packages directly where used.
The internal `@purityjs/core/internal` entry is no longer exported.

Virtual lists using `each(..., { virtual: true })` must move to `virtualEach()`
from `@purityjs/core/virtual`. Review scrolling and hydration when upgrading.
See the [entry-point and migration guide](https://github.com/KoalaFacts/Purity/blob/v0.5.1/docs/core-entry-points.md)
for the full import mapping and the [changelog](https://github.com/KoalaFacts/Purity/blob/v0.5.1/CHANGELOG.md)
for other changes.

## Package size

In a local build of merged source `de06b067`, the core, signals and compiler
npm archives totalled 333,157 compressed bytes, compared with 947,461 bytes for
the published 0.4.0 core archive: a 64.8% reduction. This measures installation
archives, not a browser bundle; archive sizes can vary by build environment.
An earlier full-root browser bundle comparison decreased by approximately 18.3%
gzip. See the [merged-source archive measurement](https://github.com/KoalaFacts/Purity/blob/v0.5.1/benchmark/bundle-size/evidence/2026-11-02-core-pack-50/merged-main-local.json)
and the [earlier audit and reproduction details](https://github.com/KoalaFacts/Purity/blob/v0.5.1/benchmark/bundle-size/evidence/2026-11-02-core-pack-50/README.md).

## Package documentation

All eight packages include a README. The CLI now scaffolds projects using
the 0.5.1 package set.

## Other changes

- The Vite plugin defaults to strict client-only AOT. SSR clients and hydrated
  component libraries must use `purity({ hydratable: true })`; runtime fallback
  requires `strictAot: false`.
- Component-owned reactive errors are routed to the existing `onError` chain.
- Purity's own license changes to Apache-2.0 starting with 0.5.0. Previously
  published releases remain under their original MIT license; third-party
  components retain their own licenses.
