# Purity 0.5.0 release notes

Purity 0.5.0 reorganizes the framework into focused packages and reduces the
compressed npm archives needed to install core. Upgrade all Purity packages
together and rebuild both client and server output.

## Upgrade from 0.4.0

Router, browser signals, actions, query, islands and compiler imports have
moved out of `@purityjs/core`. Install their new packages directly where used.
The internal `@purityjs/core/internal` entry is no longer exported.

Virtual lists using `each(..., { virtual: true })` must move to `virtualEach()`
from `@purityjs/core/virtual`. Review scrolling and hydration when upgrading.
See the [entry-point and migration guide](https://github.com/KoalaFacts/Purity/blob/v0.5.0/docs/core-entry-points.md)
for the full import mapping and the [changelog](https://github.com/KoalaFacts/Purity/blob/v0.5.0/CHANGELOG.md)
for other changes.

## Package size

In the recorded local build, the core installation requires the core, signals
and compiler npm archives. Their combined compressed size is 330,625 bytes,
compared with 947,461 bytes for the published 0.4.0 core archive: a 65.1%
reduction. This is an installation archive measurement, not a browser bundle
size claim. The separate full-root browser bundle comparison decreased by
approximately 18.3% gzip. See the [measurement and reproducibility details](https://github.com/KoalaFacts/Purity/blob/v0.5.0/benchmark/bundle-size/evidence/2026-11-02-core-pack-50/README.md).

## Other changes

- The Vite plugin supports opt-in strict AOT builds that fail on template
  transformation errors instead of falling back to runtime compilation.
- Component-owned reactive errors are routed to the existing `onError` chain.
- Purity's own license changes to Apache-2.0 starting with 0.5.0. Previously
  published releases remain under their original MIT license; third-party
  components retain their own licenses.
